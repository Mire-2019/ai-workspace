# ai-workspace

> **给 AI 一个能记住事的脑子，给项目一个会消失的终点。**
>
> 这是一份可直接抄的「AI 长期记忆 + 项目文件夹全生命周期管理」结构。
> 它是从一台真实工作机上跑了几个月、被坑了几轮之后沉淀下来的，不是设计出来的。
>
> 配套视频：B 站《AI 记不住你的事？我搭了记忆库 + 项目全生命周期管理》

---

## 这套东西解决两个病

| 病 | 长什么样 | 对应这一层 |
|---|---|---|
| **记不住** | 你说过的话、定过的口径、踩过的坑，散在几百个会话里；下一次开新会话，它一个都看不到 | **记忆层** |
| **堆不完** | 每个项目都从新建文件夹开始，做完就扔在那儿；一年几十个目录，谁都不敢删 | **项目层** |

底下压着**五条铁律**，管上面两层别乱来。

```
┌──────────────────────────────────────────────┐
│  记忆层   记忆 / 技能 / 资料  —— AI 知道什么   │
├──────────────────────────────────────────────┤
│  项目层   编号区 → 结案 → 淘金 → 文件夹消失    │
├──────────────────────────────────────────────┤
│  五条铁律  管上面两层别乱来                     │
└──────────────────────────────────────────────┘
```

## 一句话开始

```text
新项目 →  立编号区，写 00-入口.md
做事情 →  产出登记进入口，决策写进工作区
收尾   →  一件一件过：留下（进三个去处之一）或者删掉
结束   →  文件夹消失。不留指针空壳，不留「以后好找」
```

**最反直觉的一条：项目文件夹是「过程」，不是仓库。过程跑完它就该消失。**

所以它不是「把东西存起来」的系统，是「让东西该走的时候走掉」的系统。

## 三个去处（没有第四个）

项目结束前，每一件东西只能选两个答案——**留下**或者**删掉**。

说「先留着吧」不算答案，那只是没做决定。

判「留下」的，必须当场指明去处：

| 去处 | 收什么 | 判据 |
|---|---|---|
| ① **技能库** | 能调用一次就跑起来的：脚本、工具、方法论 | 换个空目录、只带它，还能不能跑 |
| ② **记忆库** | 知识：口径、经验、结论 | 它不用运行，只需要被问到的时候能被想起来 |
| ③ **常驻区** | 要**一直活着**的：开机自启指着它 / 被项目外的配置按绝对路径引用 | 冷启就失去意义的东西 |

> ⚠️ **第三类是补出来的。** 一开始只有 ①②，结果有个项目结案时，差点把整个 AI 引擎的配置连着项目一起删了。
> 最后是靠**「删目录之前先扫一遍谁在指着这里的路径」**这一步救回来的——这条现在是结案就绪度门禁的强制项。

## 五条铁律（速览）

| # | 铁律 | 治什么 |
|---|---|---|
| ① | **判据没跑过，只能记「已尝试」** | 嘴上说做完了 |
| ② | **没取证，就写「未取证」** | 幻觉 |
| ③ | **授权分四级（L0~L3）** | 「要不要打扰你」没有规则 |
| ④ | **干活的人没有终审权** | 自己给自己签字 |
| ⑤ | **唯一真源** | 两份文档都自称权威 |

细节与判据见 [`docs/03-五条铁律.md`](docs/03-五条铁律.md)。
