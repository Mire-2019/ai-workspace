# 五条铁律

> 这一份是整套东西里最值钱的部分。
> 上面两层的结构可以抄，这五条只能**被自己的坑教会**——但你可以少踩几次。

---

## ① 判据没跑过，只能记「已尝试」

**配置改没改成功，不看它怎么汇报，看有没有能观测的证据。**

```text
工具消失了吗？   文件落盘了吗？   门禁通过了吗？
```

三个都答不上来 → 只能写「已尝试」，不许写「已完成」。

### 为什么

因为它治的是「嘴上说做完了」，**人和 AI 都爱犯这一条**。

- 界面写着「已成功保存」，实际没落库
- 报告里写着「lint 0 error / 0 warning」，而那批改动**从来没跑过 lint**
- 命令 `exit code 0`，产出却是一个 22 kB 的空片
- 一次 CLI 调用参数被完全忽略、什么都没干，退出码依然是 `0`

**「成功码只说明进程退出了，不说明它干了活。」**

### 判决标准

| 说法 | 能不能写 |
|---|---|
| ✅「已跑 X，输出 Y，回读一致」 | 能 |
| ✅「已尝试，判据是 Z，尚未跑」 | 能 |
| ❌「已完成」「已修复」「已生效」 | **不能**——除非有可观测判据 |

### 一个推论

**「报告里的绿灯不作数。」** 门禁只认「真跑过」。
同一份报告说「lint 通过」，而那批改动自始从未跑过 lint —— **假绿灯比红灯更危险**，
因为红灯会让人停下来，假绿灯不会。

---

## ② 没取证，就写「未取证」

**不许用常识或推断去填事实位。**

引用任何事实之前，**回原始来源核对一次**。读回权威对象，不看印象。

### 为什么

因为推断填出来的「事实」和真事实长得一模一样，**下一次会被当成真的引用**。

真实的翻车：

- 一张清单上写着「某权限尚未具备」，助手照抄，据此判断这件事「做不了」；
  实际那个权限**早就具备了**，只是清单没更新。
- 多个「事实位」被常识填满，后来逐条回源核对，一半是错的。

### 判决标准

| 说法 | 能不能写 |
|---|---|
| ✅「已实测：X」+ 判据 | 能 |
| ✅「**未取证**：X」 | 能，而且必须这么写 |
| ❌「应该」「大概」「通常」「一般来说」 | 这是推断，不许当事实 |

### 一个副作用（很有用）

**「查无」必须带范围和基数。**

> 「在【已声明范围】内没找到」 ≠ 「不存在」。

对象错（查的不是同一个对象）是最常见的死法。
所以报「查无」时要写清：**在什么范围里、扫了多少个对象、用的什么检索式**。

---

## ③ 授权分四级

**把「要不要打扰你」变成一条规则，而不是每次临时判断。**

| 级 | 动作 | 处置 |
|---|---|---|
| **L0** | 只读 | 自动做，不用问 |
| **L1** | 改单个文件，可逆 | 自动做，**做完告诉你，你不同意可以撤** |
| **L2** | 跨文件改动 / 改插件源码 | **必须先提方案，等你批** |
| **L3** | 删数据、碰凭据、生产写入、不可逆架构变更 | **永远不自动** |

### 为什么这样分

- **全自动** → 早晚出一次不可逆的事故。
- **全人工** → 你被每件小事打断，等于没有自动化。
- **分级** → 日常零打扰，危险处强制刹车。

### 一条易漏的边界

**授权面必须逐字前缀判断，不能用「看起来像」。**
删除类工具永远不许枚举调用者没点名的东西。

> 实测近失：一个删除工具在目标是**文件**时，仍去收集**它父目录下的兄弟目录**并试图删除。
> 只因那个兄弟目录恰好非空才没被删掉——**空的兄弟目录会被静默销毁**。

---

## ④ 干活的人没有终审权

**自己做的结论，不能自己签字。**

尤其是让 AI 自己检查自己——**那不算检查**。

### 为什么

因为「我做了 X」和「我认为 X 没问题」是同一个人给出的，**共因故障**：
如果它的判断本来就有系统性偏差，自我复核只会复制那个偏差。

### 落地形态

- 结论必须落到一个**可归档的通道**里（不是只留在对话里）
- 终审由**另一个角色**做：要么是你，要么是另一个 agent，要么是一个**独立回读判据**
- 优先用**机器判据**做终审：外部工具回读、独立解码器、从产物本身反解

> 最硬的一类终审是**从产物本身反解回去**。
> 例：二维码矩阵生成正确 ≠ 成片里扫得出来。只有从**真实画面**里解一次，才算证明了。

---

## ⑤ 唯一真源

**同一个事实，只能有一份权威版本。**

发现第二份：**合并**，或者**删掉**。

### 为什么 —— 这是最贵的一条

真实的翻车（这条值一整期视频）：

```text
我改了一个内部机制的叫法，旧名字同时作废。
真源改干净了。
项目文档里还留着旧名字，写得很肯定，看起来一样权威。

两周后我要用它，随手翻到的是旧那份。
我按旧名字往下推，结论就是错的。
最要命的是：我当时完全没意识到。
```

**「两个真源都自称权威」的代价不是吵架，是你按过期的那份做了两周的决策。**

### 落地形态

| 做法 | 说明 |
|---|---|
| **引用机制名，必须回真源核对一次** | 不许凭印象，不许凭「我记得」 |
| **废弃的机制名要能被检出** | 过时名字出现即报红，而不是靠人记得 |
| **决策改真源时，同步全仓找引用** | 决策改的是真源，副本不会自己改 |
| **新功能上之前先确认它比真源更新** | 否则它就是一个新真源 |

### 一个衍生纪律（同样重要）

**永久条款必须写清楚什么时候失效。**

一条规矩里只要出现「**本次 / 本轮 / 迁移 / 重建 / 一次性**」这类时点词，
它就不该出现在永久的位置上（红线 / 契约 / 纪律 / 反模式）。

> 真实翻车：为一次迁移做的完整性证明，写下了「只改路径，不改内容」。
> 迁移完了，这条约束**没退场**，被写进红线、区契约、日常纪律三处，而且没人写它什么时候解除。
> **七天后**，文档描述的是一套事实，磁盘上是另一套——代码里悄悄成了真正的真源。

**判据：逐条问「它什么时候失效？」——答不出来的，是设计缺陷，不是纪律。**
