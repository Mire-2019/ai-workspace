# 编号区契约

> 项目文件夹只允许有这几个编号区。每个区只放一类东西，**不许串**。
> 一个文件该去哪，问三个问题就定了：**谁写的 / 给谁看 / 活多久**。

---

## 一、根的形态

```text
<项目名>/
├── 00-入口.md          ← 唯一的人类入口（也是索引）
├── 10-工作/            ← 决策进行时
├── 20-知识库/          ← 封版资产正典
├── 30-周期产物/        ← 每一期的交付物
├── 40-代码/            ← 流水线逻辑
├── 50-数据/            ← raw / interim / processed 三层
├── 90-证据/            ← 判据与实测记录
└── 99-过程包/          ← 机器 WIP，人勿开
```

**根目录除 `00-入口.md` 外，只有编号区目录。** 不许有散落文件，不许有「临时」「新建文件夹」「待整理」。

---

## 二、每个区只干一件事

| 区 | 放什么 | 不放什么 |
|---|---|---|
| `00-入口.md` | 红线、当月待拍板收件箱、区契约、开工提示词。**每个产出物在这里登记一行** | 长篇正文、方案全文 |
| `10-工作/` | 决策进行时的东西：地图与票、交接快照、轮次复盘、进度台账 | 已封版的结论（那是知识库） |
| `20-知识库/` | **拍板后**封版的正典：编号文档、runbook | 还在改的草稿 |
| `30-周期产物/` | 按周期分目录的交付物；一期一个子目录 | 中间过程文件 |
| `40-代码/` | 真正做到「流水线逻辑」的代码与工具 | 一次性探针脚本 |
| `50-数据/` | `raw`（原封不动）/ `interim`（中间）/ `processed`（成品） | 交付物（那是周期产物） |
| `90-证据/` | 判据、实测记录、守恒基线、外部不可复现的读数 | 可再生的中间物 |
| `99-过程包/` | 机器 WIP、一次性实验 | **任何还需要人看的东西** |

---

## 三、三问落子（唯一的判定动作）

拿一个不知道放哪的文件，依次问：

1. **谁写的？**
   人写的 → 往知识/产物侧；机器写的 → 往数据/过程包侧。

2. **给谁看？**
   给人看 → `00-入口` / `20-知识库` / `30-周期产物`；
   给机器看 → `50-数据` / `99-过程包`；
   给**未来的审计**看 → `90-证据`。

3. **活多久？**
   活到项目结束 → 留在本区；
   **活过项目结束 → 它就不是项目的东西，现在就该搬走**（见下）。

> **第 3 问是三问里唯一会改变项目边界的。**
> 凡是答案不是「活到项目结束」的，它就是要升格的资产，不是项目文件。

---

## 四、入口文件是唯一的人类入口

这一条是整套契约的杠杆点。

**接手一个项目，只读 `00-入口.md` 就应该够。**

所以入口里必须有：

- 红线：这个项目绝对不能碰什么
- 收件箱：**当月待你拍板的请求**（机器可维护的区块标记）
- 区契约与三问落子
- **产出物登记表：每个产出物一行，「文件 + 一句话说明」**
- 开工提示词：新会话接手时该说什么

做不到「只读入口就够」，说明产出物没登记，契约没落到位。

---

## 五、可执行的东西不许住在项目里

**工具是资产，资产住技能库或常驻区。**

项目文件夹最终要删除。今天把脚本放在项目里，明天它就跟项目一起被删掉。

> **判断标准：这个文件在项目消失后还有人要用吗？**
> 有 → 它现在就该搬走（能调一次就跑的进技能库；要一直活着的进常驻区）。

---

## 六、落地清单

- [ ] 根目录除 `00-入口.md` 外只有编号区目录
- [ ] `50-数据` 分了 `raw / interim / processed`
- [ ] 入口里有「产出物登记表」，且每条产出都登记了
- [ ] 入口里有「待拍板收件箱」，且用机器可维护的区块标记包着
- [ ] 没有散落的「临时」「待定」「新建文件夹」
- [ ] 没有可执行工具直接住在项目根或产物区（要么在技能库，要么在常驻区）
