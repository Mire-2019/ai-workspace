# 踩过的坑（26 条）

> 这一份里每一条都对应一次**真实翻车**，没有一条是从别处抄来的最佳实践。
> 按主题分组，不是按严重程度——第 1 条就够贵了。

---

## 一、关于「删东西」

### 1. 「可再生 ⇒ 可删」是个陷阱

**配方重出的是「当前态」，不是被记录的那一刻。**

一个文件可以「重新生成」，但它**不能重新生成成当时那个字节**。
所以判定要问的不是「能不能重出」，而是：
**它是不是被某份证据点名为判据/基线、并记了哈希？** 是 → 单独拎出来让人现场拍。

### 2. 「写了可删」不等于「删了」

只登记不执行 = 把「分流」退化成「搬家」。

**这类失败特别爱伪装成进度**：清单出来了、报告写了、会开了——东西一个没动。
判据只有一条：**执行过，并且删后复算剩余 = 0。**

### 3. 把某个去处当第二个项目文件夹

什么都往里搬，那个去处就成了下一个「档案馆」。

**这就是「档案馆」这个建制死掉的原因**：它唯一的用途是「可审计性」，
而这个用途概率极低，为它维护一套档号/级别/保管期限不值得。

### 4. 归档是「追加」，不是「重建」

凡是**被反复写入的区域**（索引、登记表、台账），必须假定为**累计**。
按单次运行重建 = 静默抹掉上一次的编目行。

### 5. 留指针空壳

「这个文件夹留着以后好找」——**那叫索引，索引也是指针，也是空壳。**

### 6. 删除类工具自己的作用域也要逐字限定

实测近失：一个删除工具在目标是**文件**时，仍去收集它父目录下的**兄弟目录**并试图删除。
只因那个兄弟目录恰好非空才没被删掉——**空的兄弟目录会被静默销毁**。

> **删除类工具永远不许枚举调用者没点名的东西。**

### 7. 「剩余清点」自己会造假红灯

删净之后，清点函数把「根目录已不存在」记成一条残留，报「剩余 1、失败」，
**而实际是 0**。

**凡清点函数，必须把「对象已不存在」与「对象不可读」分开判。**

### 8. 空目录 ≠ 干净项目

已结案的空壳上跑体检，会输出一份**很漂亮的报告**。计数只在非空对象上有意义。

### 9. 删目录最后一步可能删不掉

如果它正是**当前会话的工作目录**，删除必报「忙」。
先做阳性对照（排除加密层/磁盘占用），留命令给下一次会话。

## 二、关于「搬东西」

### 10. 搬一个「别人还在引用」的目录前，必须先扫外部引用者

把命中按三类分别处置：

| 类别 | 处置 |
|---|---|
| **活可执行** | 要改指新址 |
| **冻结成件**（已外发、记了哈希） | **不就地改**，出新名承接件 |
| **琐碎提及** | 保留不动 |

否则「搬得成」可以同时是「引用面全断」。

### 11. 复制工具也会造半成品，而且是静默的

实测：一个复制脚本遍历时只判断 `isDirectory()`。
**junction 既不是目录也不是普通文件** → 被当文件读 → 抛 `EISDIR` → **崩在复制中途**，
目标只有 60% 的文件，而源看起来完好。

**修法**：预检守卫（源含链接且未给策略 → 「开写前」中止）+ 按对象类型分别遍历。

### 12. 哈希全等 ≠ 属性也搬了

只读位、隐藏位这类**文件系统属性不属内容**。
实测中三件只读夹具的内容哈希三层判等全部一致，**属性却在目标侧丢光**。

**搬运验收必须分别声明「内容」与「属性」两项结论。**

### 13. 人工门如果长期没人填判定列，它就不是门

实测：82 张审校表，判定列 **0/82** 填写。这类门应当在取消前，先把「未执行」记录为缺陷。

## 三、关于「判据与验证」

### 14. 「0 命中」必须配阳性对照

在 junction 树上做检索会**静默假阴性**。
同一条命令里要再跑一个**已知有命中**的检索式——它也必须命中，否则这个 0 不算数。

### 15. 报「查无」要带范围与基数

「在【已声明范围】内没找到」 ≠ 「不存在」。
**对象错（查的不是同一个对象）是最常见的死法。**

### 16. 界面消息与后端数据都会撒谎

「已成功保存」可能没落库；「未更改」可能已改。
**唯一裁判是独立回读。**

### 17. 用「受控通道」检测「受控通道的加密」逻辑上不可能

透明加密环境下，用同一个被信任的进程去读「文件有没有被加密」——
它会用透明解密后的明文告诉你「没加密」。

**要检测加密，必须换非受控通道。**

### 18. 结论必须连「测量时的状态前提」一起记

同一件事的结论可能被反复反转——三次测量时**页面状态都不同**。
「随机点一下看看」式探测永远不该写进资产。

### 19. 判「环境坏了」之前先看资源

渲染报「浏览器启动超时」且浏览器一行日志都没有。
真相是：同机并发的活儿把内存挤到了 1.6 GB。

### 20. 归因到「已知的可怕原因」前先隔离变量

把「脚本跑不起来」归因成加密层，真相只是输入 JSON 带了个 BOM。

## 四、关于「工具与迁移器」

### 21. 空操作也会有成功码

`spawnSync` 在 Windows 上找不到 `npx.cmd`（无 shell 时），
`status` 是 `null` 的静默失败。

**包装函数必须区分两种失败**：进程没起来（ENOENT）vs 起来了但失败（非 0 退出码）。

### 22. 一个字段不要承载两种语义

一个「不逐件哈希」的标记，被下游工具误读成「不用搬」，
导致整个依赖目录漏搬，被守恒验证当场判失败。

### 23. 一个名字不要承载两种语义

两个脚本里同名的 `bail()`，一个抛异常、一个只延迟退出。
调用方以为它抛，实际它没抛 → 继续往下跑 → 崩在 `undefined` 上。

### 24. 复制/校验/删除工具都是同一个 `walk()`，会一起崩、一起漏判

修一个要同时改三个。**别指望只修一处。**

### 25. 让外部程序读「自己进程写的文件」——先想清楚加密层

透明加密/DLP 环境下，**同一份文件在不同进程眼里是两份不同的东西**。
一条可用原则：

> **中间产物可以由「自己人」写（自己读得回来）；交付物必须由「外人」写（别人才读得到）。**

### 26. 为「一次性动作」发明的约束，被固化成永久政策

真实翻车：为保证一次迁移不出错，写下「只改路径，不改内容」。
迁移完了，这条约束**没退场**，被写进红线、区契约、日常纪律**三处**，
而且**全文没有任何解冻触发器**。

**七天以后，正典与事实分叉，事实真源事实上搬进了代码——两个真源都自称权威。**

> **纪律：任何永久条款必须写明「何时解除」。**
> 理由里含「本次 / 本轮 / 迁移 / 重建 / 一次性」等时点词的约束，
> **一律不得进永久政策位**（红线 / 契约 / 纪律 / 反模式）。
>
> **同族教训**：这条在第 3 轮已经被命名为「泛化把一次事实变成一条规则」，
> 但只回灌进了「可再生判定」这一处判据，**没升格成通用纪律** → 同一病在另一个项目原样复发。
>
> **判据：一条教训若能被换个场景重犯，它就必须以「禁令 + 判据」的形式进铁律，而不只进某一节的操作说明。**
